## DL-03-1 · Що робити з розходженням PAM vs PSP · 2026-09-03

**Контекст.** Книга зведена (balanced). Виписка PSP на **$0.01** більше по captured. Касир «зелений». Фінанси просять «підкрутити».

| Варіант | Вердикт |
|---|---|
| Ігнорувати, бо $0.01 і desk balanced | **Reject** — внутрішня зведеність ≠ recon |
| Провести `recon_adjust` $0.01, щоб збіглось | **Reject** — ховає діру, немає ключа платежу |
| Усереднити PAM і PSP | **Reject** — два source of truth |
| Відкрити **break** (сума, період, які ключі не зійшли). Книгу не патчити, поки не знайдено причину | **Adopt** |

**Чому.** $0.01 сьогодні — втрачений webhook або комісія без рядка. Патч без ключа = другий автор книги.

**Інваріант.** Поки break відкритий, `cash_at_psp` у PAM **не** підганяють під файл PSP мовчазною проводкою.

**Переглярити, якщо** договір з PSP фіксує fee $0.01 окремим типом рядка — тоді це іменована проводка комісії з ключем `fee:…`, не «підкрутка recon».

## DL-03-2 · Два HTTP ставки vs один рядок · 2026-09-03

**Контекст.** Гра логує 2× `POST /bets` на `rnd_1`. PAM має один `bet:rnd_1`. Ops бачить «не зійшлось 2 vs 1».

| Варіант | Вердикт |
|---|---|
| Це break: PAM занизив ставку | **Reject** |
| Це очікуваний replay того ж `round_id` | **Adopt** |

**Інваріант.** Recon PAM↔гра по **ключах раундів**, не по лічильнику HTTP.

**Kill.** Рахувати запити гри як FILL.
