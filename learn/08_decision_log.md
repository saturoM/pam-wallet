## DL-08-1 · Матриця гейтів (наш продукт) · 2026-09-04

**Контекст.** Коли вимагати KYC: на депозит, на гру, на вивід?

| Варіант | Вердикт |
|---|---|
| Усе заблоковано до KYC | **Reject** для цього продукту — конверсія; не наш money-path lock |
| KYC на депозит | **Reject** — уже вбито в lectures |
| До KYC: депозит + ставка; вивід лише після **verified** | **Adopt** |

**Інваріант.** Три дії гейтяться окремо. Юрисдикція з KYC-at-signup — рядок у модулі 10, не мовчазна зміна desk.

**Kill.** «Немає KYC = не можна грати» без окремого market config.

## DL-08-2 · Submit ≠ verified · 2026-09-04

**Контекст.** Гравець натиснув Submit KYC.

| Варіант | Вердикт |
|---|---|
| Submit = одразу verified + вивід | **Reject** |
| Submit = **pending**; 0 проводок; вивід ні | **Adopt** |
| Submit пише `player_cash` | **Reject** — це не гроші |

**Інваріант.** TAKE статусу (заявка) ≠ FILL статусу (verified). Касир не ставить verified сам.

## DL-08-3 · Webhook вендора ≠ PAM · 2026-09-04

**Контекст.** KYC-провайдер шле `approved`. Каса хоче показати Verified з сирої відповіді.

| Варіант | Вердикт |
|---|---|
| UI / гейти читають вендора напряму | **Reject** — розсинхрон |
| PAM обробляє сигнал і пише `kycVerified` (ключ `kyc_id`); лише тоді FILL статусу | **Adopt** |

**Інваріант.** Джерело правди для гейтів виводу — прапорець PAM, не останній HTTP від Sumsub-like вендора.

**Kill.** «Вендор сказав ok = можна payout».

## DL-08-4 · Reject не void-ить раунд · 2026-09-04

**Контекст.** KYC rejected. У `bets_in_play` $10 (`rnd_1`).

| Варіант | Вердикт |
|---|---|
| Void як на self-ex | **Reject** — KYC ≠ RG |
| Lose в house | **Reject** |
| Раунд **живе**; settle як завжди; вивід і так закритий без verified | **Adopt** |

**Інваріант.** Відхилення документів не чіпає in-play. Self-ex void — інший модуль (04).

## DL-08-5 · EDD = третій рівень · 2026-09-04

**Контекст.** Після звичайного KYC risk просить джерело коштів.

| Варіант | Вердикт |
|---|---|
| EDD = той самий Reject + Submit | **Reject** — плутає рівні |
| EDD = посилена перевірка; може тримати вищий ліміт / review-hold, доки не done | **Adopt** |
| EDD блокує депозит як «немає KYC» | **Reject** для default цього модуля |

**Інваріант.** Рівні: немає KYC → verified → EDD done. Не зводити EDD до повторного reject.

## DL-08-6 · Freeze ≠ KYC failed · 2026-09-04

**Контекст.** Ops ставить freeze «бо KYC не пройшов».

| Варіант | Вердикт |
|---|---|
| Один статус `blocked` на KYC fail і AML | **Reject** |
| KYC reject = немає verified (вивід ні; гра з кишені за нашим default ок). Freeze = окремий AML/ops прапорець (немає виводу і нового входу) | **Adopt** |

**Інваріант.** Різні причини, різна політика зняття. Self-ex — третій (платити можна).

**Kill.** «Не пройшов KYC → freeze».
