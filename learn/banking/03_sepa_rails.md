# Лекція 03 · SEPA як продукт

Одна ідея: SCT і Instant — різні **продуктові обіцянки**, не «просто швидше».

## Два рейли

| | SEPA Credit Transfer (SCT) | SEPA Instant |
|---|---|---|
| Час | години / банківський день | секунди (ліміти схеми) |
| Обіцянка UI | «надіслано / в обробці» | «доставлено» лише після final |
| Fail mode | return пізніше | reject/return швидше, але не «магія» |
| Ціна / ліміти | зазвичай дешевше | дорожче, caps |

## Міст з PAM

Cascade / soft decline: не «добий той самий payment_id». Нова спроба = **новий id** платежу (як новий `deposit_id`).

## Продуктові розвилки

- Показувати Instant за замовчуванням чи SCT?
- Що бачить клієнт між accepted і settled?
- Хто платить fee Instant — клієнт чи продукт?

## Правило

> Instant ≠ «можна кредитити/розкредитовувати без статусної таблиці». Ідемпотентність і finality status — обов’язкові.
