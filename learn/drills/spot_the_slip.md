# Відповіді (після свого речення)

**S1.** Дві розвилки в одному рядку: (а) коли кредитити депозит, (б) коли холдити вивід. Депозитний pending без проводки **не** копіюється на вивід. Справжній рядок виводу = DL-4, без 3DS.

**S2.** Скопійовано депозитний TAKE. На цьому desk клік виводу після гейтів **уже проводка** `withdraw:wd_1`. Pending вивід ≠ pending депозит.

**S3.** Allowlist кнопки, не стан рахунків. Інваріант: після дозволеного Withdraw цих $ немає в `player_cash` (вони в `withdraw_in_flight`), навіть якщо UI зламаний і клікнуть ще раз — другий `wd_1` = 0 рядків / інший id потребує $ яких уже немає.

**S4.** Статус-як-спека. На desk 403 = `GateBlocked` (різні `gate`), 409 = `InsufficientFunds`. Клієнт читає `code` і `gate`.

**S5.** Між гейтами і accept кишеня жива: можна поставити й «вивести» більше, ніж є. Adopt: холд **одразу після гейтів**, потім PSP. Немає $ → немає рядка, PSP не кличемо.

**S6.** 1 факт · 2 рішення · 3 задача · 4 ніщо з трьох (meeting note).

**S7.** «Чому» протік у walk. Sequence лишає крок і 0 рядків. Чому — у `decision_log.md` / DL-02.

**S8.** Дві ідентичності (header і `roundId`) → два retry-сюжети. Adopt: business id у тілі, ключ книги похідний (`bet:rnd_1`). Окремий header на цьому slice вбито.
