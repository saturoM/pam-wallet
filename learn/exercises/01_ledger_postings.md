# Практика 1 · Pending ≠ captured · розбір

Лекція: `career/learn/01_money_path.md`.

Гравець `p_1` хоче депозит **$50** карткою.

## 1. 3DS ще не пройшов

**Касир:** доступно $0 + статус Processing / «підтверди в банку». Не Success, не +$50.

**Ledger:** `player_cash` не змінювався. Є заявка `dep_1` у pending.

## 2. 3DS успіх, webhook ще в дорозі

**Ні, ставку не даємо.** 3DS ≠ captured. Кредитимо `player_cash` лише коли PSP підтвердив списання (webhook або запит статусу того ж `deposit_id`). Доти баланс 0.

## 3. Webhook `captured` двічі

**Один раз $50** у `player_cash` на один депозит.

Спека: *проводка captured ідемпотентна по `deposit_id` (id платежу в PSP), не по id доставки вебхука.*

Два кліки Deposit → два різні `deposit_id` → $100. Два вебхуки одного `dep_1` → $50.

Пастка: унікальний `webhook_event_id` на кожну доставку. Якщо ключувати по ньому — повтор виглядає як другий депозит.
