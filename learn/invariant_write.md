# Інваріант · як сформулювати

Лекція 1 сказала *що це*. Тут — *як написати речення, яке можна перевірити*.

## Одна дія

Береш підозру («гроші не повинні зникати») і робиш з неї **знімок стану**, не побажання.

Не: «користувач не повинен втрачати гроші».  
Так: «після будь-якої події сума всіх конвертів гравця + house + сейф збігається з тим, що зайшло мінус те, що вийшло».

Друге можна взяти в облік і сказати «так / ні». Перше — ні.

## Три шаблони речення

Пиши одним з них. Якщо не лізе — ще не інваріант.

| Шаблон | Форма | Питання собі |
|---|---|---|
| **Завжди** | Завжди *P* | *P* істинне на *кожному* знімку, включно з «нічого не сталось»? |
| **Ніколи** | Ніколи немає стану *Q* | Можу намалювати *Q* як рядок у книзі / клітинку UI? |
| **Той самий ключ** | Повтор події з тим самим id не змінює *P* | Що саме є id факту, не id листа? |

«Після кроку 3 зроби X» — шаблон спеки, не інваріанта. Інваріант не знає номер кроку, він знає стан.

## Знімок, не історія

Інваріант перевіряють на **фото** системи в момент T: баланси, заявки, ключі в книзі.

Не перевіряють на розповіді: «спочатку людина натиснула, потім ми подумали». Якщо для перевірки треба намір у голові касира — речення ще не інваріант.

Можна дивитись два фото підряд (до події / після). Тоді інваріант про **дельту**: «ця подія або не змінила книгу, або додала рівно одну зведену проводку». Це все ще про стан, не про UX.

## Гардероб (без PAM)

Номерок видали — пальто прийняли. Номерок здали — пальто віддали.

| Речення | Вердикт |
|---|---|
| Черга має бути короткою | Вимога. Не інваріант |
| Завжди: кількість пальто в гардеробі = кількість виданих і ще не зданих номерків | Інваріант, зведення |
| Ніколи: два пальто на один номерок | Інваріант, заборона |
| Другий показ того самого номерка не видає друге пальто | Інваріант, ідемпотентність |
| Показуємо гарний бейдж «у черзі» | Задача |

Ламає зведення: видали номерок, пальто не прийняли (або прийняли й викинули без рядка).  
Не ламає: людина стоїть у черзі, номерка ще немає.

## Типові дірки в формулюванні

1. **Слова про людей, не про стан:** «ніхто не обдурить» — не зловиш.  
2. **Прихована норма:** «доступно коректне» — що таке коректне? Треба формула.  
3. **Залежність від шляху:** «якщо клікнули двічі швидко» — інваріант не каже «швидко»; каже про два факти з одним id.  
4. **Змішали UI і книгу:** «кнопка сіра» може брехати, книга — ні. Інваріант грошей — про книгу. UI може бути окремий (слабший) інваріант: «число на касирі = запит до книги», не «кнопка сіра».  
5. **Один рядок про все.** Краще три короткі, ніж одне «система консистентна».

## Як PO/PM це каже вголос

Не: «давайте зробимо надійніше».  
Так: «ось речення. Покажіть стан, де воно бреше — або тест, що воно тримається після дубля / фейлу / нульової дії».

Якщо інженер питає «а що якщо PSP мовчить?» — ти не вигадуєш крок. Ти кажеш, який знімок дозволений, поки PSP мовчить (заявка є, конверт гравця ще 0 — і це *не* порушення, якщо інваріант так написаний).

## Тези

> Формула інваріанта перевіряється на знімку стану, не на історії кліків.

> Шаблон: завжди *P* / ніколи *Q* / повтор id не змінює *P*.

> Немає малюнка зламаного стану — речення ще слоган.

> UI і книга — різні інваріанти. Не зливай в одне «все правильно».
